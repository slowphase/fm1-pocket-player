# FM-1 Pocket Player: what this fork adds

This repository is a fork of Jake Handy's [FM-1 Browser Simulator](https://github.com/jakehandy/fm1-browser-simulator)
(MIT). It adds a firmware library: a searchable picker over a catalogue of `.rfm1` builds that is refreshed
nightly. Everything Jake's simulator does is kept as it was.

## New files

| Path | What it is |
| --- | --- |
| `src/pocket-picker.js`, `src/pocket-picker.css` | The picker: search, favourites, New badges, categories, a preview with a Play button, the credits footer. |
| `pocket/catalog.mjs` | Builds `data/catalog.json`, `data/fw/` and `data/shots/` from approved `.rfm1` files and RemoteFM1FW's card text. |
| `pocket/upstream.mjs` | Reads what RemoteFM1FW offers: its README table (licences, sources, † and ‡ marks), card text and release files. |
| `pocket/validate.mjs`, `pocket/smoke.mjs` | The checks every firmware must pass, and the boot test (in its own process, with a time limit) that also takes the screenshot. |
| `pocket/sync.mjs` | The nightly decision: keep, update, reject, hold for review, remove. Builds the site's data. |
| `pocket/review.mjs` | The GitHub issues: review requests you approve with a label, and failure reports that close themselves. |
| `pocket/policy.json` | What may be published: the reviewed allowlist, the exclusions and the documented boot-test exceptions. |
| `.github/workflows/pocket-sync.yml` | Runs it all every day at 06:23 UTC, by hand, and when the code changes; publishes to GitHub Pages. |
| `pocket/tests/` | Tests (`npm run test:pocket`). |

`data/` is generated by the nightly job and is never committed. The published firmware files live in
the rolling release **pocket-current** (the durable copy the job recovers from).

## Changes to Jake's files

Kept small so GitHub's **Sync fork** keeps working. Each is marked with a `pocket:` comment.

**`src/app.js`**
1. `bytesOf()`: a catalogue download runs only if its SHA-256 matches the catalogue.
2. `renderList()`: hands the list to `window.FM1Pocket.render` when the picker is loaded.
3. `removeEntry()` and `window.FM1Sim`: the remove action as a function, and the few things the picker may use.
4. Startup: the catalogue's entries join the library before the first firmware is picked; `?fw=<id>` also finds catalogue ids.
5. `describe()`: the tab title uses `window.FM1_SITE_NAME` when set.

**`index.html`**: the page title and link-preview text say FM-1 Pocket Player; the picker's CSS and JS are
linked; `window.FM1_SITE_NAME` is set on its own line (so `tools/build.js` still finds the `FM1_BUILTIN` line).

**`package.json`**: a `test:pocket` script. **`.gitignore`**: `data/`.

If a merge from upstream conflicts, keep Jake's new code and re-apply the marked lines above.

## Trying it locally

```
node pocket/catalog.mjs --rfm1 <folder of .rfm1 files> --meta <RemoteFM1FW>/catalog/catalog.json --out data
python3 -m http.server 8000      # then open http://localhost:8000
```

## For the owner: day to day

Nothing to do. The job runs every afternoon (4:23 pm Queensland time). When the library changes, the
site updates; when nothing changes, nothing is republished.

**A new firmware appears.** You get a GitHub issue titled *Review: …* explaining what it is, its licence
and whether it passed the checks. To publish it, add the **approved** label (right-hand side, under
*Labels*). To leave it out, close the issue. A firmware whose licence changes gets the same kind of
issue; its last approved version stays up meanwhile.

**An update fails the checks.** You get an issue titled *Update failed checks: …*. The last good version
stays on the site. The issue closes itself when a later build passes.

**Run it now.** *Actions* tab → *Pocket sync* → *Run workflow*.

**What happened last night?** *Actions* tab → the latest *Pocket sync* run → its summary lists what was
added, updated, removed, rejected or is waiting for review.

**The schedule stopped.** GitHub switches off scheduled jobs in a public repository after 60 days with
no activity. The job commits a tiny `pocket/heartbeat.txt` every 45 days to prevent that. If it ever
stops anyway: *Actions* tab → *Pocket sync* → *Enable workflow*.

**A firmware author asks to be removed.** Add their firmware id to `withdrawn` in `pocket/policy.json`
(with the date and a note). The next run takes it down.

**Upstream changed its format and runs fail.** The site stays as it was (a failed run publishes
nothing). The run's log says which step failed; `pocket/upstream.mjs` is where RemoteFM1FW is read.
